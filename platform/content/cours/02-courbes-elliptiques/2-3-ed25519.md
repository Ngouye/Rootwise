**EdDSA** (Bernstein, Duif, Lange, Schwabe, Yang, 2011), normalisé dans la **RFC 8032** puis dans
**FIPS 186-5** (2023), utilise une courbe d'Edwards tordue, équivalente à Curve25519 :

$$-x^2 + y^2 = 1 + d\,x^2 y^2 \pmod{2^{255} - 19}$$

## Ce qui change par rapport à ECDSA

| | ECDSA sur P-256 | Ed25519 |
|---|---|---|
| Nonce | aléatoire (ou déterministe avec RFC 6979) | **déterministe par conception** : dérivé par SHA-512 d'un secret et du message |
| Formules d'addition | cas particuliers (doublement, point à l'infini) | **complètes** : une seule formule, sans branchement |
| Clé publique | 33 ou 65 octets | **32 octets** |
| Signature | 64 octets (environ 72 en DER) | **64 octets** |
| Hachage | choisi à part | SHA-512 intégré, appliqué au message complet |
| Sécurité | environ 128 bits | environ 128 bits |

Le nonce déterministe élimine la faille de la leçon précédente. Les formules complètes et
l'arithmétique sans branchement facilitent les implémentations **en temps constant**, qui résistent
aux attaques par canaux auxiliaires (mesure du temps de calcul, de la consommation électrique).

## Signer et vérifier

```bash
openssl genpkey -algorithm Ed25519 -out ed.key
openssl pkey -in ed.key -pubout -out ed.pub
openssl pkeyutl -sign -inkey ed.key -rawin -in message.txt -out signature.bin    # 64 octets
openssl pkeyutl -verify -pubin -inkey ed.pub -rawin -in message.txt -sigfile signature.bin
# Signature Verified Successfully
```

L'option `-rawin` est nécessaire : Ed25519 hache lui-même le message complet, il ne signe pas une
empreinte calculée à l'avance.

```java
// Java 15 et plus
KeyPair paire = KeyPairGenerator.getInstance("Ed25519").generateKeyPair();

Signature signeur = Signature.getInstance("Ed25519");
signeur.initSign(paire.getPrivate());
signeur.update(message);
byte[] signature = signeur.sign();

Signature verificateur = Signature.getInstance("Ed25519");
verificateur.initVerify(paire.getPublic());
verificateur.update(message);
boolean valide = verificateur.verify(signature);
```

## Sur cette plateforme

Les **certificats de réussite** délivrés à la fin des cours sont signés en Ed25519. La page de
vérification de chaque certificat explique comment enregistrer le contenu signé, la clé publique et
la signature, puis vérifier le tout vous-même avec OpenSSL :

```bash
openssl pkeyutl -verify -pubin -inkey cle.pem -rawin -in certificat.json -sigfile signature.bin
```

Modifiez un seul caractère de `certificat.json` : la vérification échoue.

## Où rencontrer Ed25519

Clés SSH (`ssh-keygen -t ed25519`), signature de paquets (OpenBSD `signify`), réseau Tor, jetons
JWT (`alg: EdDSA`, RFC 8037), certificats X.509 (RFC 8410).
