Le format des certificats est défini par la norme **X.509** de l'UIT, profilée pour Internet par
la **RFC 5280**. Un certificat est une structure ASN.1 encodée en **DER** (binaire), souvent
transportée en **PEM** : du Base64 entre `-----BEGIN CERTIFICATE-----` et
`-----END CERTIFICATE-----`.

## La structure

```text
Certificate
├── tbsCertificate            ← la partie signée (« to be signed »)
│   ├── version               v3
│   ├── serialNumber          unique pour l'AC émettrice
│   ├── signature             algorithme de signature de l'AC (ex. ecdsa-with-SHA256)
│   ├── issuer                nom de l'AC émettrice
│   ├── validity              notBefore / notAfter
│   ├── subject               nom du titulaire
│   ├── subjectPublicKeyInfo  algorithme et clé publique du titulaire
│   └── extensions            (depuis la v3)
├── signatureAlgorithm
└── signatureValue            signature de l'AC sur tbsCertificate
```

## Les extensions qui comptent

| Extension | Rôle |
|---|---|
| `subjectAltName` (SAN) | noms DNS et adresses IP couverts. **C'est ce champ que les navigateurs vérifient**, et non plus le CN du sujet |
| `basicConstraints` | `CA:TRUE` pour une AC (avec éventuellement `pathlen`), `CA:FALSE` pour un certificat final |
| `keyUsage` | usages autorisés de la clé : `digitalSignature`, `keyCertSign`, `cRLSign`… |
| `extendedKeyUsage` | usages applicatifs : `serverAuth`, `clientAuth`, `codeSigning`, `emailProtection`… |
| `authorityKeyIdentifier` / `subjectKeyIdentifier` | relient un certificat à la clé de son émetteur |
| `cRLDistributionPoints` / `authorityInfoAccess` | où trouver la liste de révocation et le certificat de l'émetteur |

Une extension marquée **critique** doit être comprise par le logiciel qui valide le certificat ;
sinon, il doit rejeter le certificat.

## Examiner un vrai certificat

```bash
# Récupérer la chaîne envoyée par un serveur
openssl s_client -connect fr.wikipedia.org:443 -servername fr.wikipedia.org -showcerts </dev/null

# Afficher un certificat enregistré dans cert.pem
openssl x509 -in cert.pem -noout -text

# Seulement quelques champs
openssl x509 -in cert.pem -noout -subject -issuer -dates -ext subjectAltName

# Empreinte SHA-256 du certificat, pour le comparer à une valeur de référence
openssl x509 -in cert.pem -noout -fingerprint -sha256
```

Dans un navigateur : cliquez sur l'icône à gauche de l'adresse, puis ouvrez le détail de la
connexion sécurisée et du certificat.

## En Java

```java
CertificateFactory fabrique = CertificateFactory.getInstance("X.509");
X509Certificate certificat;
try (InputStream in = Files.newInputStream(Path.of("cert.pem"))) {
    certificat = (X509Certificate) fabrique.generateCertificate(in);
}
System.out.println(certificat.getSubjectX500Principal());
System.out.println(certificat.getSubjectAlternativeNames());
certificat.checkValidity();                        // exception si expiré ou pas encore valide
```
